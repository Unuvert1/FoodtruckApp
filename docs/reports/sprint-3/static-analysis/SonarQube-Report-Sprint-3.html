Security Hotspots — reviewed

A Security Hotspot is a place Sonar asks a developer to look at, not a confirmed vulnerability. Both hotspots were reviewed by reading the code and the data that reaches each regular expression.

components/dashboard/onboarding-form.tsx:25

Make sure the regex used here, which is vulnerable to super-linear runtime due to backtracking, cannot lead to denial of service.

.replace(/[^a-z0-9]+/g, "-")
.replace(/^-+|-+$/g, "")
.slice(0, 40);

Verdict: not exploitable. This is slugify inside onboarding-form.tsx, which is a "use client" component: the expression runs in the visitor's own browser, on the truck name they are typing into their own form, and the result is then cut to 40 characters. /-+$/ can degrade to quadratic time on a long run of dashes, but the only machine that could be slowed is the typist's own tab. No server-side request evaluates this expression, so there is no denial-of-service surface.

lib/money.ts:71

Make sure the regex used here, which is vulnerable to super-linear runtime due to backtracking, cannot lead to denial of service.

const fraction = String(bps % 100).padStart(2, "0").replace(/0+$/, "");

Verdict: not exploitable. bps % 100 is an integer in 0–99, so after padStart(2) the subject string is always exactly two characters. /0+$/ cannot backtrack meaningfully over two characters, and the input is a computed number rather than anything a user supplies.

Both hotspots are therefore reviewed and accepted, which is what satisfies the “Security Hotspots reviewed” gate condition below. They were left in the code rather than rewritten, because a rewrite with no reachable risk would be churn; if either expression is ever moved to the server, the verdict has to be revisited.
